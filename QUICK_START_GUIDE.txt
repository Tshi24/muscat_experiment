═══════════════════════════════════════════════════════════════════════════
  CONTROLLER BEHAVIOR
═══════════════════════════════════════════════════════════════════════════

Thresholds:
  V_ON  = -10V  ← Turn thruster ON when potential drops below -10V
  V_OFF = -6V   ← Turn thruster OFF when potential rises above -6V

Logic:
  1. Potential ≤ -10V  → Thruster ON  (50W power draw)
  2. Potential ≥ -6V   → Thruster OFF (0W power draw)
  3. In between        → Hold current state (hysteresis)

Eclipse vs Sunlit:
  • Sunlit:  Uses Phi_sunlit_models.m  (typically positive at 1 AU)
  • Eclipse: Uses Phi_eclipse_models.m (typically negative)

Problem: Thruster never activates
  → Try scenario: 'AU1_eclipse' or 'AU0044'
  → Check threshold: Is V_ON too negative?
  → Check: policy_require_sunlight_for_ep = false (line 819)

Problem: No plots appear
  → Check: mission.storage.flag_save_plots = 1
  → Manual: func_plot_charging_mitigation(mission, 1)

Problem: Thruster always ON
  → Expected for AU0044 scenario (severe charging)
  → Check thresholds in Mission_DART.m
